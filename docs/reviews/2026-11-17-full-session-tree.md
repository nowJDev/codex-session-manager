# 전체 세션 트리 복구 검증 기록.

2026-11-17 기준 로컬 소스·검증 빌드는 v0.5.13이다. 백엔드·프런트 독립 리뷰와 자동 회귀, 실제 Windows production 네이티브 정상 흐름을 확인했다. 실제 RPC 조회 실패 후 삭제 차단·회복도 확인했다. 검토 후 로컬 main 통합·실행 파일 교체·임시 작업 정리까지 완료했다. 공개 릴리스는 발행하지 않았다.

## 범위와 구현 근거.

승인 설계는 [전체 세션 트리 설계](../superpowers/specs/2026-11-17-full-session-tree-design.md), 실행 계획은 [구현 계획](../superpowers/plans/2026-11-17-full-session-tree.md)이다. 기준선은 `d06dfed`이며 백엔드는 `2b36efe`·`61fb94a`·`59f976a`, 프런트는 `edf7191`에 기록한다. 후속 오류 영역 수정은 `6be182c`, 검증용 임시 파일 정리는 `c8403a8`이다.

- 동일 홈의 지원 DB를 읽기 전용으로 열어 등록 ID·보관·부모 단서를 대조한다. 기본 목록에 없는 작업 서브는 조상별 페이지와 metadata-only 단일 조회로 보충한다. 전체 갱신 동안 같은 app-server 연결을 사용하고 직접 부모 관계를 보존한다.
- SessionSnapshot의 `sessions`, `complete`, `missingCount`, `errors`를 UI·CLI·삭제 경계가 공유한다. 도중 등록 집합이 변하면 한 번 다시 수집하고 재변동·조회 실패·누락은 불완전으로 처리한다.
- 추가 파일·클라우드·DTO 변환과 병합까지 하나의 60초 예산을 전달한다. 경계·디렉터리·JSONL 라인 반복에서 만료를 확인하며 이미 확보한 행·오류·누락 수를 보존한다. 만료 후 파일 정보 확인을 생략할 수 있지만 부모·종류·등록 정보는 유지한다.
- 삭제 영향 조회·직전 재확인·사후 부재 확인은 완전한 전체 수집을 요구한다. 기본 목록 부재만으로 성공을 선언하지 않는다. 오래된 UI 콜백도 최신 삭제 gate를 확인한다.
- main·worker·guardian·otherInternal·unknown과 독립적인 요약용 표시를 제공한다. hidden 표시 계약·체크박스와 스캔 제외 경로 UI를 제거하고 기존 제외 설정은 자동요약 실행 정책에 보존한다. 표시 확대가 Guardian·요약 실행 자신·기존 제외 경로·paginated·사용 불가 기록의 자동요약 확대로 이어지지 않는다.
- 초기 전체 펼침·모두 접기/펼치기·종류 검색·검색 조상 표시·검색 전 접기 복원·상세 부모/깊이·가지 최근 활동 정렬을 제공한다. 선택과 수는 전체 논리 표시 행 기준이며 부모 선택이 자식에 자동 전파되지 않는다.
- 갱신 실패 시 이전 완전 목록·선택을 유지하고 처음부터 불완전하면 확보 행과 오류를 표시한다. 불완전 또는 오래된 목록에서는 새 완전 수집 전 삭제를 허용하지 않는다.

Rust의 제한 권한 기준선에서는 기존 Windows shim 자손 프로세스 종료 테스트가 OS 권한 제한으로 실패했다. 테스트를 약화하지 않았으며 최종 정상 권한 전체 suite는 통과했다. Vite의 제한 권한 실패도 정상 권한의 동일 기본 build 통과와 구분했다. 기존 Browserslist의 7개월 된 caniuse-lite 경고는 남겼으며 의존성을 갱신하지 않았다.

정식 빌드에서는 pnpm 대신 동일한 tsc·Vite를 실행하는 임시 훅 설정을 명령에 전달했다. 제품 Tauri 설정의 build 명령은 변경하지 않았다. 제품 패키지·Cargo·Tauri·lock 버전은 0.5.13이며 Cargo.lock의 비루트 패키지 내용은 개행을 정규화한 비교에서 동일하다.

오류 영역·임시 정리 후속 수정 이후 실제 CLI 0.169.0의 전체 API 검사와 cleanup을 다시 실행해 종료 코드 0을 확인했다. 로그의 최종 isolated PASS·Removed와 생성 임시 루트 부재도 확인했다. 정식 Tauri 재빌드는 종료 코드 0, 100,335ms이며 Cargo가 `--features tauri/custom-protocol --release`로 v0.5.13 production 실행 파일을 생성했다. 최종 실행 파일의 네이티브 정상·실패 회복 흐름 재검증도 종료 코드 0, 108,424ms로 통과했다.

초기 직접 `cargo build --release` 검증 산출물은 custom-protocol이 없어 개발 URL을 열었으므로 정상 실행 증거에서 제외했다. 이후 정식 Tauri CLI로 다시 빌드한 production 실행 파일에서 네이티브 검증을 수행했다.

## 리뷰와 수정.

백엔드 독립 리뷰에서 전체 갱신 예산이 API 수집 뒤 단계까지 전달되지 않는 Important를 발견했다. 첫 수정에서 공통 예산을 전달했고 후속 재리뷰에서 남은 클라우드 중복 읽기와 만료 후 API 확보 행 유실을 발견했다. 두 번째 수정은 캐시된 history_mode 재사용과 파일 I/O 없는 DTO 변환으로 해결했다. RED 3개를 관찰한 뒤 GREEN 및 Rust 141개 전체 통과를 확인했고 최종 백엔드 재리뷰는 승인됐다. 중복 JSONL 읽기 Minor도 함께 해결됐다.

프런트 독립 리뷰는 실제 parentId, 검색/일반 접기 분리, 논리 표시 행, 이전 완전 목록·부분 선택 보존, 최신 ref 삭제 gate와 실제 제품 훅 테스트를 확인해 승인했다. 남은 기존 Browserslist 경고는 기능 결함과 구분했다. 전체 브랜치 최종 리뷰는 `35336b5` 기준 Ready to merge Yes였다. Critical 0건·Important 0건·Minor 1건이며 Minor는 완료된 최종 네이티브 검증을 대기로 남긴 문서 상태 불일치였다. 이번 단일 문서 수정에서 CHANGELOG와 남은 작업 표기를 완료로 맞추고 현재 상태·계획의 전체 리뷰 완료를 반영했다. 기존 제품 suite·자동 검사·네이티브 실행은 반복하지 않았고 UTF-8·상대 링크·개인정보·diff 검증을 수행했다. 이 수정은 통합·배포·정리 완료를 뜻하지 않는다.

후속 Chrome 검사에서 확인한 긴 오류의 레이아웃 문제는 `6be182c`에서 고쳤다. 별도로 실제 API 검사 종료 시 Windows 읽기 전용 임시 Git 파일의 삭제가 거부되는 실패를 확인했다. `c8403a8`은 기존 소유 경계 안의 읽기 전용 일반 파일 속성만 해제하고 삭제하며 외부 경로·심볼릭링크 거부와 원래 OS 권한 오류 전달을 유지한다. Python unittest는 실제 파일 RED→GREEN과 소유 범위·권한 오류 전파 3개 전체 통과를 확인했다. 이전 실패 검사에서 남은 소유 임시 루트는 경계를 확인해 안전하게 정리했지만, 전체 worktree·브랜치 정리 완료를 의미하지 않는다.

내부 근거는 작업용 Task 1·2 보고서와 독립 리뷰, `native-success-first.json`, 최종 `native-results.json`, `tauri-release.result.json` 및 stdout/stderr 로그, Chrome 오류 영역 집계와 임시 정리 RED/GREEN 보고서, 후속 실제 API cleanup·최종 Tauri 재빌드 결과다. 이 파일들과 원본 스냅샷·화면은 비공개 작업 자료이며 제품 문서에 복사하거나 커밋하지 않는다.

## 제한과 남은 작업.

- 실제 바이너리 검증은 0.169.0이다. 0.166.0은 wire fixture 호환만 확인했으며 이번 작업에서 실제 바이너리를 확보·실행하지 않았다.
- 미지원 미래 상태 DB 스키마는 불완전 조회와 삭제 차단으로 처리한다. OS 파일 I/O 자체를 원자적으로 강제 중단하거나 다른 프로세스와 원자적 API·DB 스냅샷을 보장하지 않는다.
- 사용자 세션 삭제·네이티브 삭제 실행, 실제 모델 요약, 계정 간 클라우드 동기화 쓰기는 수행하지 않았다.
- 최종 실행 파일 네이티브 재검증·전체 브랜치 리뷰와 문서 수정의 scoped 재리뷰, 로컬 main 통합·바탕화면 바로가기 대상 교체·임시 작업 정리를 완료했다.
- 이번 작업은 공개 릴리스를 발행하지 않았다. 기존 v0.5.12 공개 발행 기록과 다운로드 링크를 보존하며 원격 최신 상태를 재조회한 것으로 해석하지 않는다.

## 로컬 통합과 마무리.

최종 문서 수정 `ea22a8c`의 scoped 재리뷰는 발견 1건 ADDRESSED·새 결함 없음으로 승인됐다. 기준 main `d06dfed`에서 `ea22a8c`로 fast-forward 통합했고 통합한 checkout에서 Rust 141개·Node 36개·삭제 VM 4개·Python 3개와 TypeScript 검사가 다시 통과했다. Rust는 컴파일을 포함해 219,484ms이며 실패·ignored는 0이다.

바탕화면 수정 버전 바로가기의 기존 대상 경로에 네이티브 검증한 Windows 실행 파일과 CLI를 교체했다. GUI 실행 파일의 ProductVersion·FileVersion은 0.5.13이며 복사 전후 SHA-256이 일치했다. GUI SHA-256은 `a424d82fdc5fad589d34ceb16a09b25aab1dc0643130dba954c50e7da81d95e2`다. 사용자 홈으로 새 앱을 자동 실행하지 않았으며 바탕화면 바로가기를 다시 실행하면 새 버전을 사용한다.

작업용 SQLite 복사본·원본 스냅샷·화면·검증 로그 등 임시 항목 561개를 경계와 reparse point 확인 후 개별 정리했다. worktree의 node_modules는 원본 의존성을 가리키는 junction만 제거했고 원본 의존성은 보존했다. 병합된 임시 worktree와 작업 브랜치를 제거했으며 원격 푸시·태그·공개 릴리스는 수행하지 않았다.
