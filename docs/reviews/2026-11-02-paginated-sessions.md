# 등록 세션 조회와 삭제 검증 기록.

기준선은 `75474d3`이며 Windows와 Codex CLI 0.166.0에서 확인했다. 사용자 세션의 원문·ID·경로·설정은 이 문서에 저장하지 않는다.

## 구현 범위.

stdio app-server adapter와 ID 기반 목록·삭제·사후 조회, nullable 파일 정보, 미리보기, 필터와 등록 수 구분을 추가했다. 수동 요약은 ID로 대화를 읽고 과거 paginated 자동 요약을 제외한다. legacy 백업 검증과 등록 확인 복원, 동일 CLI와 home 재개를 연결했다. 기존 Port 경계를 유지하고 의존성을 추가하지 않았다.

## 테스트 증거.

- 기존 기준선은 Rust 94개, Node 8개와 삭제 검사 4개가 통과했다.
- DB-only 경로/크기 nullable 회귀는 기존 문자열 필수 계약에서 RED를 확인했다.
- API 전송·페이지·부재 확인·영향 범위·결과 미확인 회귀는 구현 전 RED 후 GREEN을 확인했다.
- paginated stub, 빈 파일·잘못된 JSON·메타 없는 파일·다른 ID의 백업 덮어쓰기, 실제 로컬 checkin 검증을 확인했다.
- 사용자 지정 터미널의 선택 CLI/home, mintty/Bash 문법, Cmd 공백 경로, 독립 flags 인자를 각각 회귀 테스트했다.
- Node 전체 18개와 삭제 검사 4개가 통과했다. TypeScript 및 production build가 통과했다.
- 최종 Rust는 단위 106개·아키텍처 14개·응답성 2개, 총 122개가 통과했다. `.cmd` shim의 손자 프로세스·heartbeat·5초 내 종료 회귀도 포함한다. sandbox의 `taskkill` 접근 제한을 구분하고 정상 Windows 권한에서 전체 테스트를 실행했다.
- 실제 API 검증 스크립트는 격리 홈에 만든 legacy·paginated·보관·부모/자식 기록의 페이지 조회, 본문, Manager 목록, 연쇄 삭제, API 부재 재확인, alreadyMissing 재시도를 통과했다. 모델 turn 요청과 사용자 홈 삭제는 하지 않았고 생성한 홈은 정리했다.
- 실제 사용자 저장소는 Manager CLI의 읽기 전용 목록과 등록 정보를 비교하여 기존 CLI 세션이 포함됨을 확인했다. 데이터 변경은 하지 않았다.

## 화면과 실행.

Windows release 실행 파일을 빌드하고 프로세스·창 생성을 확인했다. Computer Use의 대상 앱 승인 대기가 시간 초과되어 네이티브 창 직접 조작은 수행하지 못했다. 해당 검증용 프로세스는 종료했다.

대신 별도 로컬 브라우저에서 실제 production 프런트에 가짜 gateway를 연결했다. 등록 3개·표시 2개·선택 수, 미확인 크기 대시, 미리보기, 숨긴 하위 항목을 포함한 선택 1개/영향 2개 확인창, 가짜 연쇄 삭제 2개와 선택 정리, 조회 실패 시 이전 목록 보존과 오류 배너를 실제 DOM·접근성 스냅샷·화면 캡처로 확인했다. 실제 세션 API에 삭제를 전달하지 않았다. 검증 페이지와 서버는 정리했다.

후속 검증에서는 외부 모델 호출 없이 임시 로컬 HTTP 응답 서버와 실제 Codex API로 paginated 세션을 생성했다. Manager CLI의 조회·삭제, 새 API 연결에서의 부재, alreadyMissing 재시도를 확인했다. 정상 Windows 권한으로 실행한 네이티브 앱에서도 격리 세션 한 개의 등록·표시 수, 이름과 미리보기를 접근성 트리와 화면으로 확인했다. 네이티브 삭제 버튼은 누르지 않았고 검증용 앱·서버·홈은 정리했다.

사용자가 재현했던 바탕화면 바로가기는 새 빌드와 해시가 다른 기존 설치본을 가리켰다. 요청에 따라 기존 설치본을 제거하고 프로젝트의 수정 빌드에 연결한 바로가기를 생성했다. 이후 사용자가 수정 버전의 정상 작동을 확인했다고 보고했다. Codex 사용자 세션과 설정은 보존했다.

## 리뷰.

스펙 리뷰 후 코드 품질 리뷰를 별도로 수행했다. 단일 페이지 긴 대화의 끝부분 누락, 형식 미확인 백업 허용, checkin에서 검증한 파일과 실제 파일의 불일치, custom 터미널 CLI/home 및 Bash·Cmd·flags 회귀, 복원 IPC의 동기 실행을 발견해 수정했다. 각 변경의 관련 테스트와 재리뷰를 수행했다. 정상 종료와 전송 제한 시간·stderr 배출도 검사한다.

Windows shim의 제한 시간 후 자기 자식 트리는 `SystemRoot/System32/taskkill.exe`로만 종료하며 다른 프로세스 이름을 검색해 종료하지 않는다. 마지막 품질 재리뷰에서 추가 차단 결함을 발견하지 못했다.

## 검증 한계.

모델 요청 없이 가져온 fixture는 공식 migration 이후에도 원본 rollout lineage에 의존했다. JSONL을 지우면 실제 API가 목록에서 제외하고 본문 조회를 거부했다. 따라서 실제 JSONL 없는 세션 삭제는 이 fixture로 검증했다고 주장하지 않는다. 파일 없는 등록 세션의 경로 무관 삭제·검증 로직은 단위 테스트로 확인하고, 실제 사용자 DB-only 목록은 읽기 전용으로 확인했다. 사용자의 실제 세션을 지워 추가 검증하지 않았다.

로컬 응답으로 만든 새 paginated 세션도 JSONL을 제거하면 실제 API가 목록에서 제외했다. 따라서 위 후속 검증도 실제 JSONL-free 삭제의 증거로 삼지 않는다. 진단 과정에서 테스트용 DB 필드를 바꾼 실험은 생성한 임시 홈에만 한정했으며 Manager 구현은 SQLite를 직접 수정하지 않는다.

네이티브 삭제 버튼 직접 클릭, 실제 모델을 사용하는 요약 실행, 실제 Google Drive 계정 간 동기화와 타 운영체제는 검증하지 않았다. 새 paginated 백업 형식과 공개 릴리스·설치 프로그램 재배포는 범위 밖이다. 소스 커밋·원격 반영과 빌드 산출물 정리는 사용자의 후속 요청에 따른다. Browserslist의 기존 오래된 데이터 경고는 의존성 갱신 범위 밖이다.
