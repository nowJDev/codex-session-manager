# v0.5.12 릴리스 실행 계획.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 사용자가 확인한 세션 조회·삭제 수정 버전을 GitHub의 최신 Windows 릴리스로 발행한다.

**Architecture:** 기존 태그 기반 `.github/workflows/release.yml`과 GitHub에 등록된 Tauri 서명 설정을 그대로 사용한다. 기능 코드는 바꾸지 않고 버전·변경 내역·검증 기록만 갱신한다. 사용자 요청으로 main 통합·푸시·발행·임시 산출물 정리까지 수행한다.

**Tech Stack:** Git, GitHub CLI, GitHub Actions, Tauri 2, Cargo, pnpm, PowerShell.

---

## Task 1. 릴리스 메타데이터와 사전 검증.

대상 파일은 `package.json`, `src-tauri/Cargo.toml`, 자동 생성되는 `src-tauri/Cargo.lock`, `src-tauri/tauri.conf.json`, `CHANGELOG.md`, `docs/current-state.md`, `docs/release-qa.md`이다.

- [x] 버전 세 곳을 0.5.12로 올리고 `cargo update --offline --package codex-session-manager`로 루트 패키지 lock 항목만 갱신했다. 이전 lock과 구조를 비교해 의존성 버전 불변을 확인했다.
- [x] 변경 내역에 등록 세션·ID 삭제 검증·기존 트리 지원 유지와 검증 제한을 기록했다.
- [x] 세 manifest와 lock의 버전 일치, Node 18개·삭제 검사 4개, 프런트 production build와 전체 diff를 확인했다. 기능 코드의 Windows Rust 122개 통과 증거는 직전 커밋에 있다.
- [ ] 검증된 릴리스 준비 변경을 한글 메시지로 커밋한다.

## Task 2. 통합과 발행.

- [ ] origin/main을 다시 확인하고 릴리스 브랜치를 main에 fast-forward 병합한다.
- [ ] main을 푸시하고 해당 커밋에 v0.5.12 태그를 생성·푸시한다. 기존 태그를 이동하거나 강제 푸시하지 않는다.
- [ ] 새 main의 CI와 태그의 Release 워크플로가 성공할 때까지 상태와 실패 로그를 확인한다.
- [ ] 발행된 릴리스가 최신·정식·공개 상태이며 설치 exe·portable ZIP·서명·latest.json을 포함하는지 확인한다.

## Task 3. 공개 산출물 대조와 정리.

- [ ] 릴리스 자산을 임시 폴더로 다운로드하고 SHA256을 GitHub digest와 대조한다. ZIP 내부 exe 버전 0.5.12와 updater 버전·URL·서명을 확인한다.
- [ ] 검증 결과를 `docs/release-qa.md`, `docs/current-state.md`와 이 계획에 기록하고 main에 커밋·푸시한다. 결과 문서는 릴리스 태그 이후의 별도 증거 커밋으로 남긴다.
- [ ] 최종 공개 exe로 바탕화면 수정 버전 바로가기의 실행 대상을 유지한다. 실행 중인 사용자 앱을 강제 종료하거나 사용자 세션을 삭제하지 않는다.
- [ ] 생성한 worktree·브랜치·다운로드·중간 빌드를 정리하고 main과 origin/main 일치, 깨끗한 작업 트리, 바로가기 대상 존재를 확인한다.

설치 프로그램을 실제 사용자 PC에 재설치하는 작업과 실제 사용자 세션 삭제는 이번 릴리스 발행 검증에 포함하지 않는다.
