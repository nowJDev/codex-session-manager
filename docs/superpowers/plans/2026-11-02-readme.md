# README 제품 소개형 개편 실행 계획.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 승인한 제품 소개형 README를 최신 공개 버전과 맞추고 GitHub에 반영한다.

**Architecture:** 제품 코드는 바꾸지 않고 GitHub가 지원하는 Markdown·HTML과 기존 로고를 사용한다. 화면 예시는 현재 프런트엔드에 격리된 샘플 gateway를 연결해 촬영하며 사용자 저장소에 접근하지 않는다.

**Tech Stack:** GitHub Flavored Markdown, Chrome DevTools, 기존 Vite production build, Git.

---

## Task 1. 문서와 화면 예시.

- [ ] `README.md`를 로고·소개·배지·다운로드·화면·기능·시작 순서로 재구성하고 최신 릴리스·기능·제한·라이선스·원작자 정보를 확인한다.
- [ ] `npm.cmd run build`로 production 프런트를 만들고, localhost의 격리 브라우저에서 샘플 세션으로 트리·상세 미리보기를 표시해 `docs/screenshot.png`를 촬영한다.
- [ ] 설정·환경 변수·개발 명령은 접는 섹션으로 보존하고 상세 검증 기록을 링크한다.

## Task 2. 검증과 반영.

- [ ] GitHub Markdown API로 렌더링하고 상대 링크·앵커·이미지·접기·최신 릴리스·배지를 검사한다. 화면 예시의 개인 정보 미포함도 확인한다.
- [ ] 전체 diff를 리뷰하고 `docs/reviews/2026-11-02-readme.md`에 실제 검증과 제한을 기록한다. 현재 상태와 진행 체크리스트도 맞춘다.
- [ ] 검증한 변경을 한글 메시지로 커밋하고 main에 통합·푸시한다. GitHub 저장소에서 데스크톱·좁은 화면의 실제 README 렌더링을 확인한다.
- [ ] 직접 만든 탭·서버·worktree·브랜치·중간 빌드를 정리하고 원격 일치·작업 트리·기존 공개 exe 보존을 확인한다.

사용자가 승인한 설계를 그대로 실행하며 추가 제품 기능·의존성·릴리스는 만들지 않는다.
