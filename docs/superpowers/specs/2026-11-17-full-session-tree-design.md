# 전체 세션 표시와 부모·서브 에이전트 트리 복구 설계.

2026-11-17 사용자가 설계안대로 구현을 승인했다. 제품 구현·검증은 이 설계와 연결된 실행 계획에 따라 진행한다.

## 1. 요구사항과 근거.

사용자는 사라진 서브 에이전트 트리를 복구하고, 가능하면 '숨긴 세션 포함' 체크를 제거하여 처음부터 내부 기록까지 모두 보기를 원한다. 현재 Manager v0.5.12의 일반 목록 조회는 Codex CLI 0.169.0에서 작업 서브 에이전트를 반환하지 않는다. 실제 DB의 격리 복사본에서 일반 목록에는 부모 ID가 있는 작업 서브가 없었고, 같은 데이터의 ancestorThreadId 조회에서는 작업 서브 5개와 각각의 부모 ID가 반환됐다. sourceKinds에 모든 서브 종류를 명시하는 것만으로 해결되지 않았다. Guardian은 일반 목록에 반환되지만 기존 hidden 규칙으로 화면에서 제외된다. 이는 서로 다른 두 문제다.

기존 React/Tauri 테이블과 Rust app-server 어댑터를 유지한다. 전체 표시와 조회·관계 복구가 이번 범위다. 원본 DB·JSONL의 편집이나 재등록, 새 Codex 홈 생성, 클라우드 포맷 확장과 자동 업데이트·원격 릴리스 발행은 범위에 포함하지 않는다.

## 2. 접근법과 권장안.

API의 기본 목록과 조상별 자손 목록을 합치는 방법은 기존 경계를 유지하지만, 부모가 기본 목록에 없는 세션이나 앞으로의 기본 필터 변경을 놓칠 수 있다. DB만 읽어 화면을 만드는 방법은 전체 등록을 발견하기 쉽지만, API와의 상태 차이와 스키마 의존성이 커진다.

권장안은 API를 실제 세션 정보와 작업의 기준으로 유지하면서, 동일 CODEX_HOME의 상태 DB를 읽기 전용으로 대조하는 방식이다. 등록 ID와 부모 단서를 통해 빠진 자손을 찾아 API로 보충하고, 조회 완전성을 확인한다. 기존 rusqlite를 사용하며 새 외부 의존성을 추가하지 않는다. DB에 직접 쓰거나 DB 조회만으로 API 작업 성공·삭제 완료를 판단하지 않는다.

## 3. 최종 화면.

기존 테이블, 상세 패널과 컬럼을 사용한다. '숨긴 세션 포함' 체크와 '숨김'이라는 표시 구분은 제거한다. 일반·작업 서브·Guardian·자동요약·기타 내부·보관 세션을 기본 목록에 포함한다. 목록을 자동으로 나누는 별도 탭이나 접힌 내부 그룹은 만들지 않는다.

첫 진입은 전체 트리 펼침을 권장한다. 모든 조회된 행을 스크롤로 볼 수 있으며, '모두 펼치기'와 '모두 접기'로 조절한다. 모두 접기는 관계상 자손만 접으며, 독립적인 Guardian 등의 루트 행은 그대로 남는다. 일반 새로고침은 현재 접기 상태·선택·스크롤을 유지하고 새로운 가지는 기본적으로 펼친다. 재실행은 전체 펼침으로 시작한다. 접기는 표시 조작이며 수집·검색·삭제 영향 범위에서 자손을 제거하지 않는다.

아래 수치와 이름은 화면 설명용 가상 예시다.

```text
Codex 세션 매니저
전체 2,300개 · 작업 서브 380개 · 현재 표시 2,300개 · 선택 0개
[세션 검색                       ] [모두 펼치기] [모두 접기] [새로고침] [설정]

이름                                 종류           마지막 활동    ...
▼ 결제 기능 수정                     일반           3분 전
  ├─ ▼ API 구현                      작업 서브      4분 전
  │    └─ 오류 처리 검토              작업 서브      5분 전
  └─ 테스트 검토                     작업 서브      6분 전
Guardian · a1b2c3d4                   Guardian       8분 전
자동요약 · b2c3d4e5                   자동요약       10분 전
작업자 · c3d4e5f6                     작업 서브      12분 전
  부모 세션을 찾을 수 없음
```

실제 관계가 확인되는 세션만 부모 아래에 배치한다. cwd·이름·시간이 비슷하다는 이유로 Guardian이나 자동요약을 특정 부모에게 붙이지 않는다. parentId가 있으나 부모 행이 없으면 해당 세션을 최상위에 남기고 설명을 표시한다. 관계를 제공하지 않는 독립 내부 기록에는 '부모 없음' 오류를 표시하지 않는다.

이름은 사용자 지정 이름, API 이름, 에이전트 닉네임, 기존의 지침 제거 규칙을 거친 미리보기, 마지막으로 종류와 짧은 ID 순으로 정한다. 종류는 색과 문자 배지를 함께 사용하고 상세 패널에서도 확인할 수 있다. 저장 형태인 로컬·클라우드와 종류 배지는 서로 구분한다. Guardian의 내부 기능을 근거 없이 '보안 검토' 등으로 단정하지 않는다.

## 4. 전체 표시의 범위.

현재 선택된 하나의 CODEX_HOME에 저장된 지속 세션을 대상으로 한다. 미보관·보관을 모두 읽고, 설정된 추가 경로와 기존 클라우드 전용 세션도 기존 방식으로 병합한다. 다른 Codex 프로필을 자동으로 합치지 않는다. API의 일시적 ephemeral 세션은 지속 저장·관리 대상이 아니므로 이번 전체 표시 범위에서 제외한다.

기존 hidden 조건에 해당하던 Guardian·자동요약·표시 제외 경로의 등록 세션은 모두 표시한다. excludedScanPaths를 등록 목록의 표시 제외 조건으로 사용하지 않는다. 사용자 설정 값은 보존한다. 추가 파일 검색에서도 '모두 표시' 모드 때문에 종전 제외 조건으로 몰래 결과를 누락하지 않도록 해당 옵션의 UI와 적용을 함께 제거한다. extraProjectDirs와 WSL 탐지처럼 검색할 저장소를 지정하는 설정은 유지한다. 기존 자동 요약의 제외 정책은 별도의 실행 조건으로 보존한다.

## 5. 전체 세션 수집.

하나의 공통 수집기를 목록·삭제 영향 범위·삭제 전 재확인·삭제 후 확인에 사용한다. 모든 RPC는 갱신 한 번당 하나의 app-server 연결을 재사용한다.

1. 앱이 사용하는 CLI와 CODEX_HOME을 확정하고 서로 다른 홈의 API와 DB를 섞지 않는다.
2. 같은 홈의 지원되는 상태 DB를 SQLITE_OPEN_READ_ONLY로 열어 짧은 읽기 트랜잭션에서 등록 ID·보관 여부·부모 단서를 읽는다. 메시지 본문이나 인증 자료는 읽지 않는다. 지원 스키마를 명시하고 알 수 없는 스키마나 읽기 실패는 빈 등록 목록으로 간주하지 않는다. 최신 번호 파일을 무조건 활성 DB로 단정하지 않는다.
3. 미보관·보관 각각의 기본 thread/list를 끝 페이지까지 읽는다. 지원 sourceKinds 전체와 modelProviders 빈 배열, useStateDbOnly=true를 명시한다.
4. 기본 결과에 없는 작업 서브를 DB ID 목록과 비교한다. 필요한 조상 ID만 고르고 ancestorThreadId를 지정하여 미보관·보관의 모든 페이지를 읽는다. 한 조상의 모든 깊이를 한 번에 받으며, 이미 수집한 하위 가지를 다시 요청하지 않는다. Guardian 각각에 불필요한 자손 조회를 보내지 않는다.
5. 부모가 목록에 없거나 조상 관계가 끊긴 경우에도 DB의 실제 부모 단서로 추가 조회한다. 남은 등록 ID는 지원되는 metadata-only thread/read로 보충하고, 이때 모델 실행이나 전체 대화 로드를 하지 않는다. 단일 thread/read도 제공되지 않거나 실패하면 해당 ID를 누락 건수로 기록한다.
6. 세션 ID로 중복을 제거한다. parentThreadId를 우선하고 source.subAgent.thread_spawn.parent_thread_id를 대체값으로 사용한다. 조회에 사용한 ancestorThreadId를 각 자손의 직접 부모로 덮어쓰지 않는다.
7. 마지막에 등록 ID를 한 번 더 대조한다. 도중 생성·삭제로 달라졌으면 한 번 다시 수집한다. 다시 달라지면 완전성을 확인하지 못한 갱신으로 표시한다. 이는 원자적인 API·DB 스냅샷을 보장한다는 의미가 아니다.
8. 추가 파일·클라우드를 기존 규칙으로 병합하고 완전한 스냅샷을 화면에 전달한다. API 등록이 없는 파일을 API 등록 세션으로 바꾸지 않는다.

구형 CLI가 기본 목록에서 이미 자손을 모두 반환하면 중복 자손 조회를 생략한다. 알 수 없는 옵션을 서버가 무시해도 '오류가 없었음'을 지원 증거로 사용하지 않고 ID 대조로 누락을 확인한다. 기존 호환 버전 0.166.0과 현재 0.169.0을 회귀 검증 대상으로 삼는다.

## 6. 데이터 계약과 실행 정책.

Session의 parentId는 실제 직접 부모 관계다. 트리 구성은 종류가 무엇이든 유효한 parentId를 따른다. isSubagent 하나로 Guardian과 작업 서브를 같은 배지로 표현하지 않는다. sessionKind는 main, worker, guardian, otherInternal, unknown으로 구분하고 자동요약 여부는 독립된 isSummaryRun으로 표현하여 '작업 서브이면서 요약용'인 경우도 잃지 않는다. 과거 클라우드 메타에 없는 필드는 기존 JSONL 메타로 보강하고, 근거가 없으면 unknown으로 남긴다. 내부 종류 자체가 unknown인 경우는 숨기지 않는다. hidden은 표시 계약에서 제거한다.

조회 응답에는 sessions 외에 completeness와 누락·실패 건수를 포함한다. 삭제 전용 경로는 완전한 수집 결과만 허용한다. UI와 CLI가 같은 완전성 판단을 사용한다.

화면에 보인다는 이유로 자동요약 대상이 늘어나면 안 된다. 종전 !session.hidden이 맡던 실행 제약을 should_auto_summarize 같은 별도의 순수 조건으로 바꾼다. 내부 Guardian·요약 실행 자신·기존 제외 경로·paginated·사용할 기록이 없는 세션은 기존 자동 요약 대상에서 계속 제외한다. 수동 요약·재개·동기화는 각각의 기존 가능 조건을 따른다.

## 7. 트리·검색·정렬·선택.

트리는 세션 ID당 한 행을 표시하고 중첩 깊이를 보존한다. 자기 참조·순환은 표시 계산에서 순환 간선만 끊어 독립 행으로 남기며 원본 관계를 쓰지 않는다. 깊은 트리는 과도한 들여쓰기를 제한하고 상세 패널에서 실제 깊이와 부모를 확인할 수 있게 한다.

정렬은 같은 부모의 자식끼리, 최상위 묶음끼리 적용한다. 기본 묶음 순서는 각 가지 전체의 가장 최근 활동 시각으로 정하여 최근에 일한 자손의 부모가 아래로 묻히지 않게 한다. 각 행의 마지막 활동 칸은 그 세션 자신의 시각을 표시하고, 가지의 최근 활동 기준이라는 설명을 정렬 도구 설명에 제공한다. 즐겨찾기는 같은 계층의 기존 우선순위를 유지하며 자식을 부모 밖으로 이동시키지 않는다.

검색은 수집된 전체 세션에서 이름·설명·ID·닉네임·종류를 찾는다. 일치 세션과 존재하는 조상을 표시하고 그 경로를 펼친다. 검색과 무관한 형제는 제외한다. 검색을 지우면 검색 전 접기 상태로 돌아간다. 검색 중 직접 접은 가지를 다음 렌더가 계속 강제로 펼치지 않는다.

헤더 전체 선택은 검색과 접기를 적용한 현재 표시 행 중 API 등록이 확인된 세션 전체를 대상으로 한다. 가상 스크롤을 적용하더라도 DOM에 렌더된 일부 행만 선택하지 않는다. 부모 체크는 자식 체크를 자동 전파하지 않는다. 접거나 검색해도 이미 고른 항목은 유지하며 '선택 N개 중 현재 표시 M개'를 알려 준다. 삭제 성공이나 새로고침으로 실제 사라진 ID는 선택에서 정리한다.

## 8. 삭제와 실패 처리.

부모 삭제는 Codex가 자손까지 지울 수 있으므로 확인창에 직접 선택 수와 전체 영향 수를 구분한다. 접힌 자손·검색에서 제외된 자손·보관된 자손도 포함한다. 부모·자식 동시 선택은 중복 제거한다. 삭제 직전 같은 전체 수집기로 영향 범위를 다시 조회하며 승인 범위가 늘면 재확인을 요구한다. 삭제 후에도 같은 완전한 경로로 확인하여 '기본 목록에 없음'만으로 성공 처리하지 않는다.

어느 페이지나 자손 조회가 실패하면 정상 갱신으로 표시하지 않는다. 이전에 완전한 목록이 있으면 그대로 유지하고 갱신 실패를 표시한다. 첫 실행이라 이전 목록이 없으면 확보한 행을 보여 주되 '일부 세션을 불러오지 못함'과 누락 건수를 명시하고 전체 수집 완료 전 삭제를 비활성화한다. 이후 갱신 실패로 오래된 목록을 유지하는 동안에도 삭제는 새 완전 수집과 영향 재검증이 성공하기 전 실행하지 않는다. 권한 오류·DB 잠금·미지원 스키마는 원인별로 표시하고 재시도는 새로고침으로 한다.

진행 중에는 '세션과 하위 작업을 불러오는 중'을 표시하고 최종 전체 수를 확정하지 않는다. 연결·대기열·자손 조회 중복을 관리하며 전체 갱신의 시간 예산은 60초를 권장한다. 시간 초과는 실패 상태로 남긴다. 창 종료 시 이번 조회가 만든 자식 프로세스·읽기 연결만 정리한다.

## 9. 성능과 접근성.

사용자 데이터 규모의 수천 행을 기준으로 전체 펼침·검색·스크롤을 실제 앱에서 측정한다. DOM이 과도하게 커지면 현재 테이블 행을 가상화하여 화면과 여유 범위만 그리되, 데이터·검색·선택·수집은 전체 집합을 유지한다. 새 가상화 의존성 도입 여부는 실측과 기존 도구로 결정하고, 임의의 '처음 100개만 표시' 제한을 두지 않는다. 긴 동기 계산은 캐시하고 변경된 목록·정렬·접기 상태에 대해서만 다시 계산한다.

접기 버튼은 Enter/Space와 aria-expanded를 지원한다. 접기로 선택 행이 사라지면 해당 부모로 키보드 포커스를 옮기며 상세 선택은 유지한다. 종류는 색에만 의존하지 않는다. 각 행의 보기·작업 가능 여부는 API 등록 및 기록 형식에 따라 설명한다.

## 11. 검증과 완료 기준.

자동 검증은 기본 목록에 자식이 없고 조상 조회에만 있는 경우, 다단계·여러 페이지·미보관 부모/보관 자식 및 역방향, 고아·순환·중복, DB/API 불일치, 조회 중 생성·삭제, 최신 스키마 실패, 과거 메타 보강을 포함한다. 숨김 토글 없이 Guardian·자동요약·이전 제외 경로 세션이 보이고, 이들이 자동요약 큐에 새로 진입하지 않는 회귀 검사를 포함한다. 전체 펼침·검색 시 조상·선택 범위·접기 상태 복원·종류 배지를 검사한다. 삭제 검사는 실제 사용자 기록 대신 격리한 테스트 세션으로 부모/자식 영향과 삭제 후 부재 확인을 검증한다.

실제 사용자 DB는 읽기 전용 ID 대조로 빠진 세션과 관계가 없는지 확인한다. 현재 확인한 작업 서브 수는 고정 기대값으로 하드코딩하지 않고 검증 시점의 등록 ID 집합과 비교한다. 실제 실행 파일에서 숨김 체크 부재, 처음부터 펼친 트리, 중첩·검색·전체 선택·새로고침·수천 행 스크롤을 확인한다. 소스나 브라우저 모의 화면만 검증하고 완료하지 않는다. Rust·Node 회귀, 타입 검사, 프런트 production 빌드와 Windows release 빌드를 수행한다.

완료는 일반 작업 서브와 내부 기록이 초기 목록에 포함되고, 실제 부모 관계로 트리가 구성되며, 전체 수와 선택 수가 화면 동작과 맞고, 같은 전체 조회를 사용하는 삭제 확인과 자동요약 회귀까지 통과한 상태다. 이번 설계 문서 작성 자체를 구현 완료로 보고하지 않는다.
